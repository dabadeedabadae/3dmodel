# photo-garments — постоянная инструкция для агентов

Корень этого репозитория — 3D-модуль: самостоятельное приложение Vite + TypeScript + Three.js. В папке `fitcast/`
лежит сам продукт FitCast (сайт Next.js `fitcast/frontend`, API NestJS `fitcast/src`, Docker), перенесённый сюда
со всей историей 2026-11-19 (I-65); отдельный репозиторий FitCast-architechtures больше не развивается. Модуль и
сайт — разные npm-проекты со своими `node_modules`; фигуры попадают на сайт через `npm run figure:sync` в
`fitcast/`. `fitcast/frontend/AGENTS.md` относится только к Next.js и на этот модуль не распространяется.

Перед работой прочитай:
- `FITCAST_PHOTO_GARMENTS_CLAUDE_PLAN.md` — план из 18 этапов и контрольные точки A–D
- `docs/STATUS.md` — что реализовано, что реально проверено, следующий разрешённый шаг
- `docs/DECISIONS.md` — принятые решения (стек, версии, конвенции, блокеры)
- последний `reports/stage-NN.md`

## Постоянная инструкция (из плана, применяется ко всем этапам)

Ты реализуешь FitCast Photo Garments по этому документу. Это локальный проект пользователя на MacBook, не задание на публикацию сайта.
Сначала читай CLAUDE.md, применимые AGENTS.md, docs/STATUS.md и DECISIONS.md. Сохраняй чужие изменения и старую реализацию. Используй существующий стек, если подходит.
Выполняй запрошенные этапы последовательно. После каждого сохраняй reports/stage-NN.md и обновляй STATUS. Отделяй написанный код, фактически запущенное и проверенное.
Между контрольными точками продолжай самостоятельно в пределах разрешённого блока. На A, B, C, D остановись с обзором результатов. Не спрашивай разрешение на каждую рутинную обратимую правку.
Каждый этап содержит результат, проверку и статус. Провал проверки исправляй; при настоящем блокере сохраняй выполненное и называй конкретную причину. Mock или ручной fallback не являются реализованным AI.
Для новых библиотек и моделей проверь официальную документацию, лицензию кода И весов, поддержку macOS/браузера, размер и способ получения. Закрепи версии; не полагайся на CUDA. Ключи не включай в frontend или git.
По умолчанию обработка локальная. Платные API и отправка пользовательских фото наружу не входят в этот план; такой provider может быть описан как опция, но не подключён молча.
Не извлекай сантиметры из пикселей без масштаба. Храни неизвестные области как unknown/default, а не как восстановленные достоверно.
Не обещай точную посадку, физику ткани, скрытую спинку или устранение всех теней. Сохраняй исходники и возможность ручной коррекции.
Создавай канонические шаблоны с фиксированной топологией и явными UV. Деформируй от основы без накопления ошибок. Используй стабильные ID и версии шаблона/аватара/обработки.
Не генерируй новую индивидуальную сетку произвольной одежды внешней image-to-3D моделью вместо шаблонного метода.
Блокирующие автоматические проверки должны давать ненулевой код завершения. Красивый рендер не подтверждает геометрическую корректность.
Сохраняй данные пользователя при изменениях. Освобождай URL, workers, geometries, materials и textures, когда они больше не нужны.
Рекомендатель образов, большой каталог и тканевая симуляция — отдельная последующая работа.

## Правила модуля

- **imported-body** (`imported-body/`): манекен импортируется готовой сеткой (FBX → three FBXLoader → сварка → симметризация → масштаб) и параметризуется полем деформации; читай `imported-body/docs/STATUS.md` и `DECISIONS.md`; команды `npm run ib:prepare|ib:check|ib:viewer|ib:render`. Исходные FBX и подготовленные сетки `imported-body/out/` в git по решению пользователя 2026-11-19 (I-64); лицензия сгенерированных моделей не проверена — репозиторий только приватный.
- **Архив**: `archive/` (в git не попадает, I-45) — там `lowpoly-v2`. Не развивать и не чинить. Основной манекен — одетая фигура `imported-body`.
- Манекен v1: процедурный `src/body/*` (D-22/D-23), план `docs/PLAN_MANNEQUIN_AND_FIT.md`; `npm run check:body` блокирующий; `body.html`.
- Приоритеты (D-11, пересмотрено 2026-11-02 планом манекена): цепочка фото → 3D завершена до точки C; этапы 04/13 теперь идут как F- и P-этапы плана `PLAN_MANNEQUIN_AND_FIT.md`; `TestMannequinAdapter` не развивать; категории — по очереди из плана (брюки, юбка, худи, куртка).
- Модели только локальные с проверенной лицензией (`public/models/README.md`); ручной режим никогда не выдаётся за распознавание; scores не называть точностью.

- Старая заглушка манекена `frontend/app/model/*` в FitCast перенесена в `archive/` старой рабочей папки FitCast-architechtures (не в git) по решению пользователя 2026-11-18; `/model` перенаправляет на `/fitting` с одетой фигурой.
- Стороны во всех ID — стороны носителя, левая = +X (`src/domain/sides.ts`, D-04). Сторона снимка — отдельный тип.
- `TestMannequinAdapter` — ЯВНО тестовый манекен. Интеграция с реальным FitCast Body не выполнена (см. STATUS → Integration blocker). Не называй её завершённой.
- Команды: `npm ci` (lockfile закоммичен, флаги не нужны — D-02), `npm run dev`, `npm run verify`
  (typecheck + vitest + блокирующая геометрическая проверка + build), `npm run render`, `npm run e2e:pipeline`, `npm run e2e:chain` (Playwright).
- Маска: слои model/post/user, статусы ok/suspicious — эвристики, не точность (D-20). Параметры вещи: estimated/applied/user раздельно, без сантиметров (D-15). Спинка и невидимые острова — «не восстановлено по снимку» (D-17).
- Не меняй настройки разрешений и не отключай запросы безопасности ради автоматического продолжения.
- Внешние skills (img2threejs и т.п.) не считаются установленными; основная реализация от них не зависит.
