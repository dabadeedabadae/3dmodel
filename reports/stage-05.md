# Этап 05 — Загрузка и нормализация фото
Статус: выполнено (проверено в headless Chromium; нативный macOS/Safari — не проверено)

## Изменения
- `src/pipeline/photo.ts`: выбор файла, памятка (одна вещь, спереди, ровно, рукава расправлены, контрастный фон, ровный свет; не на человеке, не куча; только футболка; ничего не отправляется). JPEG/PNG/WebP по факту декодирования браузером; HEIC — попытка декодировать, при неудаче понятное сообщение с инструкцией (без обещания поддержки). Лимит 40 МБ.
- Ориентация: `createImageBitmap(file, {imageOrientation:'from-image'})`, fallback `<img>`. Оригинальный `File` не изменяется; рабочая копия ≤ 1024 px по длинной стороне (билинейное уменьшение через canvas, без пикселизации), матрица рабочая→оригинал хранится в `PhotoRef.normalized.toOriginal`.
- Предпросмотр через object URL, `revoke()` при смене/сбросе; кнопка «Сбросить». Смена фото → `PipelineStore.setInput('photo_loaded')` стирает все зависимые результаты и отменяет задачи.

## Реально запущенные проверки
`scripts/e2e-pipeline.mjs` (Playwright/Chromium, контейнер): 8 фикстур загружены, рабочая копия 400×533 (масштаб ×1.000 — фикстуры мелкие), `text/plain` отклонён («Неподдерживаемый тип…»), поддельный `.heic` отклонён с сообщением об экспорте в JPEG, замена фото во время сегментации → `category_confirmed`/`mask_confirmed` idle, старой маски нет (`reports/stage-05-07-e2e.json → extra`). Повёрнутые (EXIF) и большие снимки в фикстурах отсутствуют — **этот путь не проверен на данных**, только код.

## Ограничения
- EXIF-поворот и downscale >1024 не покрыты данными; HEIC на Safari не проверен.
- Изображение не отправляется никуда (модели грузятся с того же dev-сервера).
