# Этап 03 — Одна ручная параметрическая футболка
Статус: выполнено, ожидает утверждения на контрольной точке A (силуэт и UV)

## Изменения
- `src/templates/tshirt/params.ts` — 14 ограниченных параметров (длина, ширины груди/подола/плеч, соотношение глубины, глубина проймы, длина рукава, радиус манжеты, наклон рукава, ширина/спуск горловины спереди и сзади, ширина воротника, наклон плеча) с min/max/default/step; `clampTShirtParams` клампит и ОТЧИТЫВАЕТСЯ о каждом клампе; производные правила согласованности (DECISIONS D-05). `TSHIRT_TEMPLATE_ID = tshirt-basic`, `TSHIRT_TEMPLATE_VERSION = 1.0.0`, `TSHIRT_TOPOLOGY_VERSION = tshirt-basic-topo-1`.
- `src/templates/tshirt/buildTShirt.ts` — одна связная low-poly поверхность: торс 6 рядов × 16 колонок, кокетка (плечевое кольцо → кольцо горловины), воротник (горловина → внутреннее кольцо), проймы вырезаны из боковых квадов рядов 3–5, рукава — 8-вершинные кольца, корневое кольцо = вершины проймы (общие). Отверстия: горловина (16), подол (16), манжеты (8+8). Без сплошного торса и пересекающихся цилиндров. 210 вершин геометрии / 158 логических / 272 треугольника.
  - Группы: `geometry.groups` на 5 островов (materialIndex 0..4); `islands[]` (вершины, диапазон индексов, UV-прямоугольник), `rings[]` (hem, waist, chest, armpit, shoulder, neck, collar_inner, armhole_*, cuff_*), `seams[]` (боковые, плечевые, подрукавные, задний шов воротника), `logicalIndex` (геом. вершина → логическая) для проверок топологии без сварки по координатам.
  - UV: пять островов (front, back, sleeve_right, sleeve_left, collar), считаются от канонических параметров и НЕ меняются при деформации; панели сужены по ряду (плоская выкройка). Единая плотность текселей `uvScale = 0.3626` uv/м.
  - `updateTShirt()` — деформация на месте от канонической базы (позиции пересчитываются целиком, ничего не накапливается), нормали по логическим вершинам (гладкие швы).
- `src/templates/checks.ts` — 20 проверок (манифолдность, ориентация, граничные петли, связность, UV в [0,1], непересечение островов с gutter 0.01, знак UV-площади = зеркальность, растяжение, X-симметрия, направление граней от оси части, bbox) + `checkFixedTopology` (индексы/логические/UV идентичны при случайных параметрах).
- `scripts/check-tshirt.ts` — блокирующая проверка: каноническая + 20 случайных наборов параметров; **exit 1 при провале**; пишет `reports/stage-03-checks.json`.
- `src/image/uvChecker.ts` — checker с буквами (F, R, G, 2, 4, 7 — асимметричные глифы), подписью острова, стрелкой «вверх по v», тонировкой островов; `drawUVLayout` — UV-каркас поверх checker.
- Dev-страница: виды front/back/left/right/iso, ползунки параметров, wireframe, flat shading, checker, тестовый манекен, отчёт проверок на странице, экспорт PNG/JSON. Материал — нейтральный `MeshStandardMaterial` (серый, roughness 0.85), один на остров.
- `scripts/render.mjs` — 19 рендеров + manifest.

## Автоматические результаты и ручные исправления
AI нет. Исправления в ходе этапа (все — после провалов проверок, не визуальных): (1) `cumulative()` терял последний сегмент → NaN в UV; (2) ключ симметрии давал «-0.00000»; (3) проверка «нормаль острова» заменена на «каждая грань от своей оси» — усреднённая нормаль у усечённого конуса рукава ничего не доказывала; (4) ряды торса пересекались при большой пройме и короткой длине → ряды заданы долями остатка длины + clamp `armholeDepth ≤ 0.6·length`; (5) горловина выходила за плечевое кольцо по Z → clamp по глубине; (6) рукава складывались при узких плечах/большом наклоне → ось рукава = нормаль кольца проймы, первое кольцо всегда впереди самой выступающей вершины проймы; (7) прямоугольная развёртка кокетки растягивала UV ×2.1 → трапециевидная выкройка (×1.38).

## Ограничения и ошибки
- Это шаблон, а не примерка: футболка лишь поставлена по высоте шеи тестового манекена; руки манекена проходят сквозь рукава — ожидаемо до этапа 04.
- Канонические размеры подобраны под чиби-пропорции тестового тела (грудь 0.44 при радиусе торса 0.36); при реальном теле FitCast канон потребует пересмотра (топология при этом не меняется).
- Рукава крепятся к боковой стороне торса («boxy» крой, без плечевого свеса); при `shoulderHalfWidth < chestHalfWidth` ось рукава (нормаль проймы) поднимается — это честная геометрия, но силуэт может выглядеть «крыльями». Вопрос для точки A.
- Нет проверки самопересечений (рукав ↔ торс при экстремальных наклонах и больших манжетах); производные clamp'ы снижают риск, но не доказывают отсутствие.
- UV-атлас заполнен неплотно (острова ~40% площади) — плотность текселей равномерна, оптимизация раскладки не в объёме.
- Flat-шейдинг доступен переключателем, по умолчанию гладкие нормали.
- Проверено только в Chromium (headless). Safari/Firefox на Mac — нет.

# Ревизия A-1 (2026-10-29, после обратной связи по точке A)
Статус: выполнено, точка A по-прежнему ожидает утверждения

## Изменения
1. **Стороны носителя.** Все семантические ID переименованы: `sleeve_left`/`cuff_left`/`armhole_left`/`side_left`/`shoulder_left` = **+X = левая сторона носителя**; `*_right` = −X. Тестовый манекен (`arm_left`, `shoulder_left`, `wrist_left`…) приведён к той же конвенции. Новый модуль `src/domain/sides.ts`: типы `WearerSide` / `ImageSide` и единственный мост `imageSideToWearerSide(side, view, mirrored)` (спереди без зеркала image_right→left; сзади image_right→right; зеркало переворачивает). Зависимые проверки обновлены (`faces_point_outward`, порядок островов, регионы манекена).
2. **Рукава не поднимаются.** Ось рукава теперь — нормаль хорды проймы (подмышка → плечевая вершина), одна и та же функция `rows.armholeRingElevation` в билдере и в clamp. Правило `elevation ≤ sleeveAngle`; при нарушении `shoulderHalfWidth` расширяется бисекцией до минимально допустимого, кламп виден в UI (`.pg-clamp`) и в `clampTShirtParams().clamped`. Boxy-крой (плечи = грудь) разрешён при любом наклоне. Узкие плечи допустимы ровно настолько, насколько компенсирует наклон. Кольца рукава центрируются на оси (раньше центр манжеты смещался из-за неравномерных углов вершин проймы). Новая блокирующая проверка `sleeves_do_not_rise`.
3. **Установка без `--legacy-peer-deps`.** Причина сбоя — баг arborist npm 10.9.x на взаимных optional-peer `vitest ⇄ @vitest/browser-playwright/-webdriverio` (vitest ≥ 4.1.0), не конфликт наших версий. Lockfile перегенерирован npm 12.2.1 без флагов; `npm ci`/`npm install` на npm 10.9.9 с этим lockfile проходят чисто. `.npmrc` удалён. Детали и проверенные комбинации — DECISIONS D-02.
4. **Путь интеграции с Body.tsx** — `src/fitting/Object3DBodyAdapter.ts` + `docs/INTEGRATION_BODY.md` (что доступно сейчас / чего не хватает). Body.tsx не изменён.
