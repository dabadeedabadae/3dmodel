# Этап 07 — Удаление фона и маска
Статус: выполнено; ревизия B-1 (замечания точки B учтены, см. раздел ниже)

## Изменения
- `U2NetpSegmentationProvider` (`src/providers/SegmentationProvider.ts`): U²-Netp (Apache-2.0, 4.6 МБ, `sha256 309c8469…`), вход 320×320, выход → мягкая маска 0..255 в координатах рабочей копии; постобработка: порог 128, крупнейшая 4-связная компонента, заливка замкнутых дыр ≤ 15 % кадра. Эвристики качества: покрытие <5 % / >90 %, касание границы >15 % периметра, несколько регионов → `suspicious` с предупреждениями; `empty` при нулевой маске. Настоящий вырез/промежутки не заливаются автоматически, если они соединены с фоном.
- Редактор (`src/pipeline/maskEditor.ts`): overlay (фон затемнён, контур маски жёлтый), кисть добавить/стереть с размером, undo (25 шагов), зум 0.5–4×, прозрачный crop. Координаты — пиксели рабочей копии. Подтверждение маски — отдельная кнопка; `MaskRef.source = estimated` (без правок) или `user_adjusted`; при сбое модели — явный ручной режим с пустой маской.
- Инференс в Web Worker (`src/pipeline/worker.ts`), UI не блокируется; замена фото отбрасывает результат.

## Ревизия B-1 — замечания точки B
1. **Ползунок порога.** Мягкая карта модели (0..255) хранится; `rethreshold(result, t)` пересчитывает бинарную маску и постобработку без повторного инференса (e2e: при 128 покрытие 0.479 → при 64 0.485 → обратно 128 0.479, «восстановлено» = true). Если есть ручные штрихи, движение ползунка не стирает их: показывается запрос «пересоздать маску из модели с новым порогом?» с явной кнопкой (`applyThreshold → 'needs_confirmation'`; e2e `thresholdAfterEdits.strokesKept = 3`).
2. **Слои маски.** Хранятся раздельно: `model` (порог без постобработки), `post` (крупнейшая компонента + заливка только мелких замкнутых дыр ≤ 0.5 % площади вещи — `post-v2`), `user` (правки). Удалённые фрагменты не теряются: кнопка «вернуть фрагменты» возвращает компоненты модели; большие дыры (вырез!) **не заливаются автоматически**. Кнопки «залить внутренние разрывы, кроме крупнейшего» (вырез остаётся) и «залить все» — явные действия пользователя с undo. Предупреждение «внутренние разрывы: N (x % площади)» показывается отдельно от статуса.
3. **Эвристические статусы.** `ok / suspicious / empty` — результат эвристик (покрытие, касание границы, фрагменты, внутренние разрывы), не точность: ручной разметки нет, точность маски не заявляется. Подтверждение пользователем (`MaskRef.source`, стадия `mask_confirmed`) и эвристический статус — разные поля (`maskLayers.user.status` может быть `suspicious` при подтверждённой маске — так и у синей футболки).
4. **Категория.** Ручной выбор категории всегда доступен (кнопки для каждой категории + «неподдерживаемая»); ImageNet jersey — не детектор всех футболок (подписано в UI, D-12, D-21).
5. **EXIF и большие файлы** (`fixtures/special/`, e2e `extra.special`, проверка против эталона sharp в node): 3000×4000 без EXIF, EXIF 3/6/8 → рабочая копия 768×1024, ориентация верна во всех 4 случаях, MAE к эталону 0.22–0.25/255 (ресемплинг); PNG/WebP 400×533 — MAE 0. Только Chromium; Safari/macOS не проверено.

Синяя футболка 91ebc326: модель — 8 фрагментов, после постобработки 1 компонента 37 %, после 3 штрихов 41 %, внутренние разрывы остаются (1, 0.4 % после «залить кроме крупнейшего»); визуально в ткани большие просветы. **Маска НЕ считается исправленной** — это сложный пример для ручной коррекции (user.status = suspicious).
