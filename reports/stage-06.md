# Этап 06 — Выбор и проверка распознавания
Статус: выполнено — реальный локальный автоматический вызов; качество ограниченное и честно измерено

## Выбор
Исследованы варианты (DECISIONS D-12). Из сборочной среды доступны только npm и GitHub, поэтому выбран ImageNet-классификатор **MobileNetV2-12** из ONNX model zoo (Apache-2.0, 14 МБ, `sha256 c0c3f76d…`) на `onnxruntime-web` 1.31.1 (wasm, 1 поток, в Web Worker). CUDA не требуется. Классы → категории: 610 jersey/T-shirt → tshirt; 608 jean → pants; 655/689/601 (*skirt) → skirt; остальное → other. Поддержаны категории футболка / брюки / юбка / другое; шаблон только у футболки (`CATEGORY_TEMPLATE`), брюки на футболку не направляются.

## Интерфейс
`CategoryProvider` (id, version, description, load, suggest, dispose) → `CategoryResult` с top-k предложениями (масса softmax по категории, подпись в UI «не вероятность и не точность»), сырыми top-5 классами ImageNet и временем инференса. Подтверждение — отдельная кнопка; запись хранит `suggestions`, `confirmed`, `manual`. При сбое провайдера — баннер «РУЧНОЙ РЕЖИМ», `manual: true`. `ManualCategoryProvider` никогда не выдаёт предложений.

## Реально запущенные проверки
1. `npm run eval:fixtures` (node, тот же код провайдера) на 26 реальных CC0-фото: **футболки top-1 11/14**, **не-футболки отклонены 11/12** (платье b2279dec принято за футболку), всего 20/26. Инференс 44–81 мс, загрузка моделей 587 мс. Отчёт `reports/stage-06-07-eval.json`, лист `renders/stage-06-07-contact-sheet.png`.
2. e2e в браузере (`npm run e2e:pipeline`): предложения показаны с сырыми классами; пользователь исправил категорию для 8f0cd82c (модель: jean) и 2df565b9 (модель: sarong) — запись помечена «исправлена пользователем»; брюки/юбка/обувь после подтверждения отклонены сообщением «ЭТА КАТЕГОРИЯ НЕ ПОДДЕРЖИВАЕТСЯ…», маска не строится.

## Ограничения
- Это ImageNet-модель, не одежный классификатор: ошибки на длинных/сложных футболках (sarong, sleeping bag) и путаница джинсовой юбки с брюками. Доля ручных исправлений на наборе: 3/14 футболок.
- Scores некалиброваны; порогов отклонения нет — решает пользователь.
- CLIP/fashion-модели не подключены (нет доступа к HF из сборочной среды); интерфейс провайдера позволяет добавить.
- Ручной режим не выдаётся за распознавание.
