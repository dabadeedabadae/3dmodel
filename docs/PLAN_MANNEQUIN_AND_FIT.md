# План: low-poly манекен, посадка одежды и образы

Версия 0.2 (решения по открытым вопросам приняты 2026-11-02, работа начата с M01). Продолжение `FITCAST_PHOTO_GARMENTS_CLAUDE_PLAN.md`: закрывает отложенные этапы 04 (подгонка под фигуру) и 13 (фигура и позы) и добавляет несколько вещей на одном теле. Постоянная инструкция из основного плана действует без изменений.

## 0. Что должно получиться

1. **Параметрический low-poly манекен** (Three.js, генерируется кодом, без Blender): фиксированная топология, 10–12 понятных параметров фигуры (рост, плечи, грудь, талия, бёдра, длины рук/ног…), именованные области тела и ориентиры, скелет для простых поз.
2. **Посадка** одной вещи из `photo-garments` на этом манекене без пересечений с телом: вещь сохраняет свои пропорции с фото, подбирается масштаб и «прибавка на свободу» (ease), а не перекраивается силуэт.
3. **Образы (outfits)**: несколько вещей одновременно — футболка + брюки, поверх — кофта/куртка; порядок слоёв, заправлено/навыпуск, без z-fighting и прострелов нижнего слоя через верхний.
4. Всё — локально, в браузере, с сохранением в локальный гардероб. Без тканевой симуляции и без обещания «точной посадки»: это визуальная примерка на упрощённом теле.

## 1. Ключевые решения (предлагаю зафиксировать до начала)

**Манекен — процедурный, а не скачанный.**
Варианты, которые рассматривал:
- SMPL/SMPL-X — лицензия только для некоммерческого исследования, веса нужно скачивать с регистрацией → не подходит для продукта.
- Mixamo / Ready Player Me / VRoid — чужие аватары, лицензии на использование вне их экосистем ограничены, топология высокополигональная и не наша → не подходит как основа.
- MakeHuman (CC0 экспорт) — можно, но это внешняя программа и ручной экспорт на каждое изменение фигуры.
- **Процедурное тело из колец сечений** (как уже сделан шаблон футболки): торс — стопка эллипсов вдоль позвоночника, конечности — конусные трубки, голова — сфера/капсула. Полностью под контролем, фиксированная топология, любые пропорции меняются параметрами, стиль low-poly совпадает с одеждой. Это и выбираем. Оставляем точку расширения: импорт glTF-тела с именованными костями как альтернативный `AvatarAdapter` (позже).

**Единицы.** Тело и одежда — в одних относительных единицах (канон шаблона футболки: ширина груди 0.88). Сантиметры появляются только если пользователь вводит рост — тогда масштаб один на весь аватар, и это явно подписано.

**Посадка = выравнивание по ориентирам + радиальная проверка колец + выталкивание из тела.** Не физика. Пропорции вещи с фото (длина, ширина, рукава) не меняются молча: если вещь по фото уже тела (подол уже бёдер), вещь показывается «в натяг» со статусом `tight`, а не расширяется тайком. Пользователь может включить «подогнать по телу» явно.

**Слои.** Каждый следующий слой садится не на тело, а на «огибающую» предыдущих слоёв (максимум радиуса по кольцу) + своя прибавка. Порядок слоёв фиксирован по категориям, с ручным переопределением.

**Пересечения.** Проверка — аналитическая дистанция до набора капсул/эллиптических колец тела (без воксельных SDF и без GPU). Блокирующая автопроверка: ни одна вершина верхнего слоя не внутри тела/нижнего слоя.

## 2. Этапы

Нумерация продолжает основной план: M = манекен, F = посадка, O = образы, P = позы. Контрольные точки: **E** (манекен), **F** (одна вещь сидит), **G** (образ из 3 вещей), **H** (позы).

### M01 — Контракт тела и параметры фигуры · **выполнено** (reports/stage-M01-M04.md)
- `BodyParams` (10–12 параметров, лимиты, пресеты S/M/L и «по умолчанию»): рост (относительный), ширина плеч, обхват груди/талии/бёдер как полуширины и глубины, длина торса, длина рук, длина ног, толщина рук/ног, размер шеи/головы.
- Расширить `AvatarAdapter`: `getLandmarks()` (neck_base, shoulder_L/R, armpit_L/R, chest/waist/hip lines, wrist_L/R, crotch, knee_L/R, ankle_L/R), `getCrossSection(regionId, t)` — эллипс сечения тела на высоте t, `getCapsules()` для проверок пересечений, `getRegions()` с семантическими ID (стороны носителя, как в D-04).
- Проверка: vitest на монотонность (больше параметр → больше сечение), симметрию L/R, лимиты. Результат: `src/body/params.ts`, `src/body/BodyAdapter.ts`, тесты.

### M02 — Процедурная сетка манекена · **выполнено**
- Торс: N колец × M вершин (как `tshirt-basic`), от бёдер до основания шеи, с плечевым скатом; шея и голова; руки и ноги — трубки по оси с 3–4 кольцами (плечо, локоть, запястье; бедро, колено, щиколотка), кисти и стопы — упрощённые капсулы. Один связный меш или 6 частей с общими стыками — решить по проверкам.
- Фиксированная топология `body-basic-topo-1`, `logicalIndex`, деформация от канона без накопления ошибок (`updateBody(params)`).
- Проверки (блокирующий скрипт `check:body`, exit 1): конечные значения, нет вырожденных треугольников, манифолдность, нормали наружу, симметрия L/R, кольца не пересекаются при любых параметрах в лимитах (стресс 300 случайных наборов), конечности не входят в торс в A-позе.
- Рендеры: спереди/сзади/3-4/сверху, wireframe, пресеты S/M/L.

### M03 — Скелет и скиннинг (без поз) · **выполнено**
- Кости: hips, spine, chest, neck, head, shoulder_L/R, upperArm, forearm, hand, thigh, shin, foot (≈17). Положение — из тех же параметров фигуры.
- Веса — аналитически по близости к капсуле кости (гладкие переходы на суставах), `SkinnedMesh`. Проверка: сумма весов = 1, в A-позе скиннинг не искажает сетку (поза покоя = сгенерированная).
- Это фундамент для P-этапов; позы здесь не делаем.

### M04 — Страница манекена и форма параметров · **выполнено, ждёт утверждения E**
- `body.html`: ползунки фигуры, пресеты, виды, wireframe, отчёт `check:body` на странице, экспорт JSON параметров. Ввод роста в см — опционально, включает подпись размеров (один масштаб).
- **Контрольная точка E**: манекен с проверками, рендерами, отчётом.

### F01 — Выравнивание вещи по телу · **выполнено** (reports/stage-F01-F04.md)
- Для футболки: совместить `neck_base`/плечи вещи с телом по высоте и ширине плеч; масштаб вещи выбирается из одного ориентира (ширина плеч или груди — настраивается), остальные пропорции — с фото. Рукав направляется по оси руки (A-поза).
- Для каждой категории — свой список «якорных» ориентиров (брюки: талия/бёдра/промежность, длина ног).
- Результат: `src/fitting/align.ts`, матрица размещения в записи вещи (`GarmentRecord.fit`).

### F02 — Прибавка и радиальная проверка колец · **выполнено**
- Для каждого кольца вещи — сечение тела на той же высоте; требуемый радиус = тело + ease (по категории и по слою; значения в таблице, редактируются). Статусы по кольцам: `ok / tight / loose`. Если ease нарушена — вершины выталкиваются радиально (без изменения высоты), сглаживание по соседним кольцам, чтобы не было «ступенек».
- Пропорции с фото сохраняются в `params.resolved`; изменения от посадки — отдельный слой `fitAdjust` (provenance), с переключателем «показать как с фото / подогнать по телу».
- Проверка: ни одна вершина вещи не внутри тела (по капсулам/сечениям), max penetration = 0, рукав не пересекает торс, подол/манжеты вне тела. Блокирующий `check:fit` на 3 пресетах тела × 4 футболках из точки C.

### F03 — Низ: шаблон брюк и юбки
- Шаблоны `pants-basic` (пояс-кольцо, две трубки-ноги, фиксированная топология, UV: перед/зад каждой ноги + пояс) и `skirt-basic` (конус/трапеция). Ориентиры по фото для брюк (пояс, промежность, низ штанин, ширина колена) — тем же методом силуэта.
- Цепочка `photo-garments` расширяется на эти категории (сейчас в реестре только tshirt). Проверки геометрии как для футболки.

### F04 — Просмотр вещи на манекене · **выполнено для футболки**
- В `garment.html` переключатель «отдельно / на манекене», выбор пресета тела, отчёт статусов колец (tight/loose), подсветка проблемных мест. Футболка сидит, брюки сидят — по одной.
- **Контрольная точка F**: 4 футболки из точки C + 2 брюк на пресетах S/M/L, рендеры, `check:fit` PASS.

### O01 — Порядок слоёв и огибающая
- Таблица слоёв: `bottom: pants|skirt = 1`; `top: tshirt = 1, shirt/longsleeve = 2, sweater/hoodie = 3, jacket = 4`; обувь отдельно (не сейчас). Переопределение вручную.
- «Огибающая» тела после надевания слоя k: по каждому кольцу/капсуле — max(тело, вещи слоёв ≤ k). Слой k+1 садится на огибающую. Верх над низом: правило «навыпуск» (подол поверх пояса с ease) / «заправлено» (подол под пояс, обрезка внутри).

### O02 — Устранение прострелов между слоями
- Проверка пересечений верхнего слоя с нижним (как с телом). Там, где нижняя вещь полностью перекрыта верхней, — скрывать перекрытые треугольники нижней (по углу и расстоянию) вместо увеличения ease: иначе куртка «раздувается».
- `renderOrder` + небольшой polygon offset для оставшихся близких поверхностей. Автопроверка: 0 вершин нижнего слоя снаружи верхнего в зоне перекрытия после скрытия.

### O03 — Образ как запись
- `OutfitRecord`: список `garmentId`, порядок слоёв, флаги «заправлено», выбранный пресет тела, версия посадки. Сохраняется в локальный гардероб (IndexedDB — это одновременно этап 14 основного плана). Открыть/дублировать/удалить образ, экспорт JSON + PNG.
- Страница `outfit.html`: гардероб слева, манекен в центре, слои справа (включить/выключить, порядок, заправить).
- **Контрольная точка G**: образ из 3 вещей (футболка + брюки + кофта/вторая футболка как верхний слой), 3 пресета тела, рендеры спереди/сзади/3-4, `check:fit` PASS для всего образа.

### P01 — Пресеты поз (этап 13 основного плана)
- 4–5 поз: A-поза, T-поза, руки вниз, шаг, рука на поясе. Задаются углами суставов; интерполяция между позами.
- Одежда следует телу: веса одежды копируются с ближайших вершин/капсул тела (proximity skinning). Проверка пересечений повторяется в каждой позе; где пересечение неустранимо (подмышка при руке вниз) — помечается, не скрывается.
- **Контрольная точка H.**

### P02 — Плавность и ограничения
- Сглаживание весов на суставах, ограничения углов, чтобы одежда не рвалась; статус поз «проверено / с артефактами» по каждой вещи.

## 3. Что сознательно НЕ делаем
- Тканевая симуляция, складки, драпировка.
- Автоматическое определение фигуры человека по фото.
- Скачанные аватары с ограниченными лицензиями.
- Обувь, аксессуары, головные уборы (отдельная очередь).
- Рекомендатель образов.

## 4. Порядок работ и оценка объёма
E (M01–M04) → F (F01–F04) → G (O01–O03) → H (P01–P02). Каждая точка — остановка с отчётом, рендерами и журналом фактически запущенных проверок, как раньше. Если тело FitCast (`Body.tsx`) к тому моменту получит API — подключается через тот же `AvatarAdapter` вместо процедурного; шаблоны и посадка не меняются.

## 5. Принятые решения (ответы 2026-11-02)
1. **Два пола** — два базовых набора пропорций (`male`, `female`) с одной топологией; архетипы/пресеты поверх них. Главное — ползунки фигуры с анатомически правдоподобными пропорциями: соотношения строятся от канона пластической анатомии (рост ≈ 7.5–8 высот головы, ширина плеч ≈ 1.8–2.3 головы у мужчин / 1.6–2.0 у женщин, таз, длина бедра ≈ голени и т.д.), лимиты ползунков не пускают в невозможные сочетания (как в шаблоне футболки). Все пропорции — параметры с провенансом, а не «зашитые» числа; источники канона фиксируются в DECISIONS.
2. **Ввод роста в см — уже на E**: один масштаб на аватар; подписи в см появляются только при введённом росте.
3. **Голова и кисти — чуть детальнее** капсул: голова с подбородком/затылком и шеей, кисти — ладонь + сомкнутые пальцы одним блоком, стопы — с носком и пяткой. Без лица.
4. **Категории после брюк**: юбка → кофта/худи → куртка (в этом порядке; F03 = брюки + юбка, O-этапы добавляют худи и куртку как верхние слои).
