## 2026-10-29 · D-01 · Модуль живёт в `FitCast-architechtures/photo-garments/` как отдельное Vite-приложение
Причина: существующий 3D-код FitCast — `frontend/app/model/*` на React-Three-Fiber внутри Next.js 16. План требует «отдельный модуль, старые реализации не удалять, Three.js + TypeScript». Чистый Three.js без React-обёртки проще проверять в node (vitest) и headless-браузере; позже модуль можно подключить в Next через `<primitive>` или отдельный route.
Последствия: своя `package.json`, свой `node_modules`, порт 5174 (frontend 3001, backend 3000). Корень репозитория не меняется, кроме появления папки.

## 2026-10-29 · D-02 · Закреплённые версии и установка БЕЗ `--legacy-peer-deps` (ревизия)
three **0.185.1** (та же, что в `frontend/package.json` → совместимость будущей интеграции), @types/three 0.185.4, typescript 5.9.3, vite 7.3.7, vitest 4.1.12, tsx 4.23.15, playwright 1.63.0 (dev-only, для рендеров), @types/node 22.20.5. Все версии точные (без `^`), lockfile в git.
Почему vitest 4 (а не 3): `npm audit` на vitest 3.2.7 даёт 2 critical (tinypool, @vitest/mocker); на 4.1.12 — 0 уязвимостей.
**Конкретная причина сбоя `npm install`:** npm 10.9.x (идёт с Node 22) падает с `TypeError: Cannot read properties of null (reading 'edgesOut')` в `arborist #loadPeerSet`, когда строит дерево для vitest ≥ 4.1.0. У vitest 4.1.x есть *опциональные* peer-зависимости `@vitest/browser-playwright@4.1.12` и `@vitest/browser-webdriverio`, которые сами имеют peer `vitest@4.1.12` (взаимная optional-peer-связка). Это баг npm 10, а не конфликт версий наших пакетов: тот же `package.json` ставится npm 11.21.1 и npm 12.2.1 без флагов; vitest 4.0.18 ставится и npm 10, но имеет critical advisory. Наличие/отсутствие `playwright` в devDependencies на сбой не влияет (проверено).
**Решение:** lockfile (`package-lock.json`, lockfileVersion 3) сгенерирован npm 12.2.1 без флагов и закоммичен. С этим lockfile `npm ci` и `npm install` на npm 10.9.9 проходят **без** `--legacy-peer-deps` и без `.npmrc` (проверено в контейнере). Флаг нужен только если удалить lockfile на npm 10. Существующие `frontend/` и корень репозитория не трогались.

## 2026-10-29 · D-03 · Реальный манекен FitCast не имеет API → тестовый адаптер
Факт: `frontend/app/model/Body.tsx` — JSX-дерево примитивов (сфера-голова, капсула-торс, капсулы-конечности), «чиби»-пропорции, без параметров, версий, ориентиров, костей и доступа к поверхности. `Garment.tsx`/`templates.ts` строят placeholder-одежду цилиндрами с зазором ≥ 0.03.
Решение: контракт `AvatarAdapter` (src/fitting/AvatarAdapter.ts) + `TestMannequinAdapter`, который численно повторяет примитивы Body.tsx (числа скопированы 1:1, версия `1.0.0+src.frontend.app.model.Body.tsx@2026-10-29`) и добавляет ТОЛЬКО для тестов параметры `height`, `torsoScale`, `shoulderWidth`.
Последствие: интеграционный блокер — итоговый проход (этап 18) не может называться интеграцией с FitCast, пока у Body нет программного API или GLB с ориентирами. Что нужно от команды FitCast: (a) экспорт тела как функции/GLB с теми же конвенциями; (b) ориентиры neck_base, shoulder_*, armpit_*, chest/waist/hip, wrist_*; (c) версия тела; (d) событие изменения параметров.

## 2026-10-29 · D-04 · Конвенции координат и сторон (ревизия: стороны носителя)
Единицы — «метры» FitCast-тела (чиби ≈ 2.58 в высоту, не человеческий масштаб; подгонка относительная). Y вверх, +Z — перёд тела. Начало координат — между стопами на полу. Шаблон одежды строится в своей системе: линия плеч y = 0, подол y = −length; размещение на манекене — обязанность адаптера/подгонки (этап 04).
**Стороны.** Все семантические ID (`sleeve_left`, `cuff_right`, `armhole_left`, `shoulder_left`, `arm_left`, `side_left`…) — стороны **носителя**. Левая сторона носителя = **+X** (зритель, смотрящий на перёд, видит её справа). Сторона на снимке — отдельный словарь `image_left | image_right`; единственный мост — `imageSideToWearerSide(side, view, mirrored)` в `src/domain/sides.ts`: вид спереди без зеркала: image_right → left; вид сзади: image_right → right; зеркальный снимок переворачивает. Покрыто `tests/sides.test.ts`; шаблон и тестовый манекен проверяются на знак X.
Отменяет прежнюю «экранную» трактовку (sleeve_right = +X).

## 2026-10-29 · D-05 · Шаблон футболки `tshirt-basic` 1.0.0, топология `tshirt-basic-topo-1`
Одна связная поверхность: торс 6 рядов × 16 колонок, кокетка (плечевое кольцо → горловина), воротник (горловина → внутреннее кольцо), проймы — вырезанные квады рядов 3–5 вокруг колонок 3..5 / 11..13, рукава — 8-вершинные кольца от проймы (общие вершины), 3 кольца. 210 вершин геометрии (158 логических), 272 треугольника. Четыре отверстия: подол 16, горловина 16, манжеты 8+8.
UV: пять островов (front, back, sleeve_right, sleeve_left, collar), каждый — своя `geometry.group` (materialIndex 0..4). UV считаются от КАНОНИЧЕСКИХ параметров и не меняются при деформации (текстура, запечённая один раз, остаётся валидной). Панели переда/спинки сужаются по ряду (плоская выкройка), поэтому растяжение 0.87–1.36 вместо 2.1 у прямоугольной развёртки.
Нормали усредняются по логическим вершинам → швы UV не дают ступеньки освещения.
Ось рукава = нормаль (в плоскости XY) хорды проймы «подмышка → плечевая вершина» с наклоном вниз на `sleeveAngle` (см. D-08); кольца рукава центрируются на оси (среднее радиальное смещение вершин проймы вычитается); первое кольцо рукава всегда впереди самой выступающей вершины проймы (+0.03). 300/300 случайных наборов параметров проходят.
Производные ограничения параметров (clamp с отчётом): горловина внутри плечевого кольца (по X и по Z), `armholeDepth ≤ 0.6·length`, `neckFrontDrop ≤ 0.6·armholeDepth`, `shoulderSlope ≤ 0.4·armholeDepth`, `|shoulderHalfWidth − chestHalfWidth| ≤ 0.1`.

Блокирующие: `scripts/check-tshirt.ts` (exit 1 при провале) и `vitest`. Рендеры (`scripts/render.mjs`) — доказательство визуального результата, не корректности. Проверка «буквами» на checker-текстуре дополняет автоматическую проверку знака UV-площади (зеркальность), а не заменяет её.

## 2026-10-29 · D-07 · Что НЕ сделано намеренно до точки A
Подгонка к телу (этап 04) — футболка на dev-странице только размещена по высоте шеи тестового манекена; руки манекена проходят сквозь рукава, это ожидаемо. Фото, распознавание, маски, UV-перенос, пикселизация — не начаты.

## 2026-10-29 · D-08 · Рукава не поднимаются выше горизонтали (ограничение сочетаний параметров)
Проблема (точка A): при `shoulderHalfWidth < chestHalfWidth` кольцо проймы наклоняется вверх, и рукав с малым `sleeveAngle` задирался («крылья»). Ракурсом это не скрывается.
Решение: ось рукава определяется хордой проймы (`rows.armholeRingElevation`), одинаково в билдере и в clamp. Правило: `armholeRingElevation(params) ≤ sleeveAngle`. Если нарушено — `shoulderHalfWidth` расширяется бисекцией до минимального значения, при котором правило выполняется (отчёт о клампе показывается в UI и в `clampTShirtParams().clamped`). Boxy-крой (плечи = грудь) разрешён при любом `sleeveAngle ≥ 0` — у него подъём ровно 0. Узкие плечи разрешены ровно настолько, насколько их компенсирует наклон рукава (например, плечи 0.42 при груди 0.5, пройме 0.3 и наклоне 0.5 рад — без клампа). Проверка `sleeves_do_not_rise` (центр манжеты не выше центра проймы) — блокирующая.

## 2026-10-29 · D-10 · Горловина: плечевое кольцо = линия плеч (шаблон 1.1.0)
Проверка сверху и в 3/4 (запрос пользователя) показала плоскую «крышку»: плечевое кольцо имело глубину 0.78·глубины груди (0.27), а горловина — 0.14, и кокетка превращалась в диск с дыркой. Исправление в `rows.ts`: глубина плечевого кольца = min(глубина груди, 0.85·neckHalfWidth + 0.03); ряд 4 сохраняет 75 % глубины груди, чтобы перёд оставался вертикальным и вырез читался как разрез переда, а не отверстие в куполе. Топология не изменилась (`tshirt-basic-topo-1`), версия шаблона 1.1.0. Побочный эффект: растяжение UV на кокетке до ×2.48 (предупреждение, не блокер) — при переносе фото кокетка получает цвет/низкочастотный рисунок, поэтому допустимо; пересмотреть на этапе 10.

## 2026-10-29 · D-11 · Приоритеты: цепочка без манекена; 04 и 13 отложены
Манекен FitCast не готов. Цель — одна полностью работающая цепочка для футболки, снятой спереди на плоскости: фото → подтверждение категории → удаление фона → правка маски → оценка формы → подгонка шаблона → перенос в UV → пикселизация → просмотр (отдельно, без тела; вращение, зум, спереди/сзади/3-4, переключение исходной и пиксельной текстуры) → сохранение. Отсутствие манекена не блокирует обработку фото. `AvatarAdapter`, `Object3DBodyAdapter`, `GarmentRecord.avatar` сохраняются как контракт; `TestMannequinAdapter` не развивается, пересечения с ним не устраняются. Другие категории и рекомендатель — не сейчас. Параметры шаблона описывают саму вещь относительно (длина/ширина/рукава/вырез); без масштаба они не сантиметры; исходные оценки хранятся отдельно от ограничений и пользовательских правок (`Sourced` с provenance).

## 2026-10-29 · D-12 · Модели: ImageNet MobileNetV2-12 (категория) и U²-Netp (маска), локально, без CUDA
Ограничение среды: из сборочного окружения доступны только npm и GitHub (Hugging Face, CDN, Wikimedia недоступны), поэтому CLIP/transformers.js не использованы. Выбрано:
- Категория: `mobilenetv2-12.onnx` из ONNX model zoo (Apache-2.0, 14 МБ, ImageNet-1k). Классы 610 jersey/T-shirt → tshirt, 608 jean → pants, 655/689/601 (*skirt) → skirt, всё остальное → other. Оценка = масса softmax по категории, некалибрована, так и подписана в UI. Это не «распознаватель одежды» — на 26 реальных фото top-1: футболки 11/14, не-футболки отклонены 11/12 (одно платье принято за футболку). Пользователь подтверждает/исправляет категорию отдельной кнопкой; при сбое провайдера — явный ручной режим (`manual: true`).
- Маска: `u2netp.onnx` (U²-Netp, Apache-2.0, 4.6 МБ; файл из релиза rembg, md5 совпадает с пакетом `@planby-tech/rmbg-webgpu`). Общий salient-object remover; на 26 flat-lay фото 19 масок «ok», 7 «suspicious» по эвристикам (касание границы/несколько регионов), 0 пустых. Провалы честно видны: тёмно-синяя футболка на синем пледе теряет рукава — исправляется кистью. Постобработка: порог 128, крупнейшая компонента, заливка замкнутых дыр ≤ 15 % кадра.
- Отклонено: `@imgly/background-removal` (AGPL-3.0), BRIA RMBG 1.4/2.0 (non-commercial). CLIP остаётся опцией на будущее (нужен доступ к HF).
- Веса лежат в `public/models/` с лицензиями и sha256 (`public/models/README.md`); грузятся браузером с того же dev-сервера, ничего не уходит наружу.
- Инференс — `onnxruntime-web` 1.31.1 (MIT), wasm, 1 поток, в Web Worker (UI не блокируется). Тот же код провайдеров прогоняется в node скриптом `scripts/eval-fixtures.ts`.

## 2026-10-29 · D-15 · Лимиты шаблона расширены до реальных пропорций (шаблон 1.2.0)
Оценки по фото (длина 1.28, рукав 0.2 отн. ед. и т.д.) выходили за лимиты, рассчитанные на чиби-манекен. Лимиты `tshirt-basic` расширены (length ≤ 1.6, sleeveLength, cuffRadius, neck); канон, топология `tshirt-basic-topo-1` и UV не изменились; все 21 проверка + стресс 300/300 проходят в новом диапазоне. ## 2026-10-29 · D-16 · Ориентиры: геометрия силуэта + явные значения по умолчанию
Без обучаемой модели ориентиров: контур → выпуклая оболочка → дефекты (подмышки) → плечи/манжеты/подол по контуру. Горловина на flat-lay обычно не видна силуэтом → стороны и низ выреза ставятся по умолчанию (0.42 ширины плеч) с `source: 'default'`, `status: 'uncertain'` и всегда редактируемы. Любой сдвиг точки — `user_adjusted`; невидимые на фото параметры (глубина, спинка, воротник) — из шаблона, так и подписаны.

## 2026-10-29 · D-17 · Перенос в UV: кусочно-аффинно по треугольникам, условные острова
Перёд — сетка рядов (подол/талия/грудь/подмышка/пройма/плечо/горловина) с краями по маске и косинусными колонками, как на эллипсе шаблона; рукава — только видимая передняя половина. Каждый треугольник острова переносится аффинно (барицентрика) внутри подтверждённой маски; одной гомографии нет. Спинка, воротник, задняя половина рукавов, разрывы маски — заливка основным цветом и флаг `conditionalIslands` («не восстановлено по снимку»). Ориентация: image-right = левая сторона носителя = +X; автоматическая проверка знаков корреляции u↔x, v↔−y.

## 2026-10-29 · D-18 · Цвет: медиана и низкочастотная коррекция, по умолчанию выключена
Основной цвет — медиана внутри эродированной маски без 5 % крайних по яркости. Коррекция освещения — деление на маскированное низкочастотное поле яркости (радиус ~W/6), сила 0..1, по умолчанию 0; усиление 0.4…2.5. Не albedo. Сырая и скорректированная UV хранятся отдельно.

## 2026-10-29 · D-19 · Пикселизация: только текстура, дизеринг по умолчанию выкл
Box-даунсемпл атласа 64/128/256 + median-cut палитра + сила смешивания; Флойд–Стейнберг опционален (на однотонной ткани даёт шум). Желоба залиты основным цветом → без каймы. Меш не меняется. Просмотр: `NearestFilter` на увеличении + mip на уменьшении.

## 2026-10-29 · D-20 · Маска: слои model/post/user, порог без повторного инференса, дыры не заливаются автоматически
Карта модели хранится; порог пересчитывается из неё (`rethreshold`); при ручных правках смена порога требует явного «пересоздать». Постобработка `post-v2`: крупнейшая компонента + заливка только мелких замкнутых дыр (≤ 0.5 % площади вещи); крупные дыры (вырез) остаются, фрагменты можно вернуть. Внутренние разрывы — отдельное предупреждение; «залить кроме крупнейшего» / «залить все» — явные действия. Статусы ok/suspicious — эвристики, не точность; подтверждение пользователя — отдельный статус.

## 2026-10-29 · D-21 · Классификатор и сегментация приняты как временная основа MVP
Решение пользователя (точка B): ImageNet MobileNetV2 + U²-Netp — временная основа с обязательным подтверждением пользователем; другой ML-провайдер не подключается. Ручной выбор категории — всегда; ImageNet jersey не считается детектором всех футболок.
