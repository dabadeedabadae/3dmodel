## Проект

FitCast — сайт-примерочная. Человек загружает фото своей вещи, вещь распознаётся в браузере, её принт ложится на 3D-фигуру,
фигуру можно настраивать ползунками.

Весь проект — один репозиторий `~/Desktop/Проекты/3dmodel` (GitHub `dabadeedabadae/3dmodel`, приватный). Работа этих сессий — в ветке `3d-photo-sliders-proportions` (от `main`, в `main` не влита: там работают тиммейты).
- **Корень — 3D-модуль** (Vite + TypeScript + three.js). Основное лежит в `imported-body/`: подготовка фигур из FBX, слои одежды,
  деформация ползунками, перенос фото. Распознавание фото — `src/shape/landmarks.ts`, `src/image/maskOps.ts`,
  `src/providers/SegmentationProvider.ts`.
- **`fitcast/` — сам продукт**: сайт Next.js 16 (`fitcast/frontend`), API NestJS (`fitcast/src`), Prisma + Postgres,
  Docker. Старый репозиторий FitCast-architechtures больше не развивается.
- **Копии кода на сайте.** Файлы в `fitcast/frontend/lib/garment/*` и `fitcast/frontend/lib/figure/{deform,photoMap,proportions,proportions.data}.ts` —
  дословные копии файлов модуля с первой строкой `// Ported from 3dmodel/... keep in sync`. Меняешь одно — меняй оба.
- **Обновление фигур.** Фигуры сайта (`fitcast/frontend/public/models/figure-01..04.json`) пересобираются только командами
  `npm run ib:outfits` (в корне), затем `npm run figure:sync` (в `fitcast/`).

## Правила пользователя (обязательно)

- Отвечать по-русски, просто, без лишнего жаргона.
- Коммиты **без** строки `Co-Authored-By`. Коммитит и пушит пользователь сам: дай ему готовые команды.
- В репозитории, README и на сайте не упоминать генератор моделей по имени и то, что модели сгенерированы нейросетью.
  Репозиторий приватный: лицензия моделей не проверена.
- Пароли и ключи не печатать и не вводить. Пользователь входит на сайт сам. Демо-пароли лежат только в
  `fitcast/.demo-accounts.local.json`.
- Не трогать фронт профиля и регистрации, это зона тиммейтов: `fitcast/frontend/app/profile/settings`, `login`,
  `register`, `fitcast/src/auth`, `fitcast/src/users`.
- После правок проверять самому, глазами в браузере, а не только тестами.
- Блокирующие проверки не ослаблять. Если проверка падает, искать причину.
- Сантиметры по пикселям не считать. «Нужно подтвердить» — это эвристика, а не точность.
- **Сдача — примерно 2026-11-22.** Принимающий хочет именно «фото → своя 3D-вещь».

## Как запустить локально

- **Модуль:** `npm ci`, затем `npm run verify` (типы, vitest, геометрия, сборка).
  - `npm run ib:outfits` — пересборка 4 фигур, нужен `RESULT: PASS`;
  - `npm run ib:photo` — проверка переноса фото на 19 тестовых снимках;
  - `npm run ib:check` — голый манекен.
- **Сайт целиком:** `cd fitcast && docker compose up --build -d`. Подробности — `fitcast/docs/ONBOARDING.md`.
- **Как было запущено в прошлом чате:**
  - фронт — dev-сервер на 3001;
  - API — `node dist/main.js` на 3002 из `fitcast/`;
  - Postgres — контейнер `fitcast-preview-postgres` на 55435;
  - сервис рекомендаций — в Docker на 8010.

  Порт 3000 занят Grafana, 5433 занят другим проектом.

## Фигуры

`imported-body/assets/outfits.json` — список фигур и тип вещи на каждой:

| Фигура | Комплект |
|---|---|
| 01 | футболка + брюки (эталон) |
| 02 | худи + брюки |
| 03 | рубашка + брюки |
| 04 | классическая рубашка + брюки (вещь без тела, `shirt01.fbx`) |

- **Как собирается фигура.** Все фигуры собраны слоями поверх эталона 01 (I-61/I-62). Голова, кисти и обувь у всех одинаковые
  (эталонные). Тело убрано; футболка и брюки эталона остаются внутри как скрытое тело.
- **Правило I-54.** Вещь из гардероба надевается только на фигуру с таким же типом вещи.
