# FitCast — пакет для сдачи

FitCast: сфотографируй вещь — сайт сам определит её тип, наденет принт с фото на готовую 3D-фигуру и
подберёт образы из твоего гардероба под повод и погоду, учитывая твой вкус.

## Запуск (Windows, Docker Desktop)

```powershell
cd fitcast
docker compose up --build -d
```

- сайт: http://localhost:3001
- API: http://localhost:3002, сервис рекомендаций: http://localhost:8010, Postgres: 5433

Демо-данные (пользователь с гардеробом и событиями; пароль записывается в `fitcast/.demo-accounts.local.json`):

```powershell
docker compose exec -e DEMO_CREDS_FILE=/tmp/demo.json api node scripts/seed-demo.cjs
docker compose cp api:/tmp/demo.json ./.demo-accounts.local.json
```

## Сценарий видео (2–3 минуты)

1. **Главная → вход.** Коротко: что такое FitCast.
2. **Гардероб → «+ Add item» → фото футболки.** Сайт сам ставит тип «T-shirt» («Recognized from the photo,
   please check»), предлагает цвет, видит узор, второй цвет и длину рукава («Also from the photo»), за ~2 секунды строит маску и точки — всё на устройстве, фото никуда не
   отправляется. «Add to wardrobe».
3. **«Try on in 3D».** Примерочная: принт с фото на 3D-фигуре, крутим модель, двигаем ползунки фигуры
   (рост, грудь, талия). Переключаем Men / Women, показываем пару новых вещей: водолазку, бомбер, блузку.
4. **Looks на телефоне** (в браузере — размер телефона). Образ показан на 3D-манекене. Повод «Casual», погода по городу. Свайп вправо, влево,
   ещё пару раз — блок «Your taste» меняется, у карточек появляется «+0.6 your taste»; после 8 свайпов —
   «Personal model · trained on N swipes» с тем, что модель нашла. Под оценкой — факторы: «+3 complementary
   colors», «−5 sporty and dressy pieces mixed».
5. **«Complete the look».** Совет «Navy shirt instead of your T-shirt lifts this outfit from 92 to 99» с
   картинкой; «Add to shopping list».
6. **События.** Событие «Job interview» завтра → прогноз → образы под повод и погоду; сохранить образ.
7. Итог: фото → тип → 3D → образы и вкус; цифры проверок из таблицы выше.

## Что внутри

- **3D-модуль** (корень, `imported-body/`): готовые низкополигональные фигуры (16 мужских, 16 женских), сборка
  одежды слоями на манекен, проверки пересечений и симметрии; правки сеток в Blender —
  `imported-body/scripts/blender/` (симметрия, распутывание, удаление мелких деталей, удлинение корпуса,
  расширение и подрезка горловины).
- **Фото → 3D** (`imported-body/src/photoMap.ts`, сайт `fitcast/frontend/lib/figure`): маска U²-Netp, точки,
  раскладка фото на перед верха или брюк.
- **Тип вещи по фото** (`fitcast/frontend/lib/garment`): MobileNetV2 (Apache-2.0) в браузере, ответ поправляется
  по силуэту маски (`shape.ts`): «джинсы» без двух штанин — это юбка или верх.
- **Рекомендации** (`fitcast/recommendation-service`): правила v1 — повод, погода, цвета, слои; вкус по свайпам;
  стиль (гармония цветов по цветовому кругу, цельность, контраст, вечер, свежесть), ветер; вкус — обучаемая
  модель (логистическая регрессия на свайпах пользователя, `app/engine/learn.py`); совет «докупи».
- **Сайт** (`fitcast/frontend`, Next.js) и **API** (`fitcast/src`, NestJS + Prisma + Postgres).

## Ограничения (честно)

- Принт ложится на перед; спинка и бока — основной цвет вещи, не восстановлены по снимку.
- Тип по фото — подсказка (23 из 26 фото проекта верно), человек подтверждает. Правила по форме вещи (две штанины,
  рукава, расширение книзу) подобраны на этих же 26 фото, на новых снимках доля может быть ниже.
- Рекомендации — правила плюс небольшая обучаемая модель вкуса (логистическая регрессия, не нейросеть): она
  включается с 8 свайпов, где есть и лайки, и дизлайки; на тесте со скрытым вкусом угадывает не меньше 85 %
  отложенных образов. Это проверка на синтетическом пользователе, не на реальных людях.
- «Докупи» — тип + цвет с картинкой каталога и ссылка на поиск такой вещи в магазинах (в запросе только цвет,
  тип и «men / women»); своего каталога товаров и цен нет.
- Шорты, юбки, платья на 3D-фигуре пока не надеваются (нет сборки низа без тела); женское худи не прошло
  проверку пересечений и в каталог не вошло.
- Отчёты по этапам: `imported-body/reports/stage-I7*.md`, статус — `imported-body/docs/STATUS.md`.
