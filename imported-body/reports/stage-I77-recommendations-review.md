# I-77 (2026-11-24): проверка гардероба и рекомендаций образов

Как проверялось: `npm run seed:demo` внутри контейнера API создал демо-пользователя (город London, 12 вещей из
CC0-фото и каталога, 5 событий). Скрипт входил через API (пароль читался из `.demo-accounts.local.json` и не
выводился) и запрашивал `POST /recommendations` для каждого события и для 8 поводов. Погода — реальный прогноз
(+2…+9 °C, в день театра дождь).

Гардероб: футболка серая, футболка белая (LOOSE), свитер navy, худи, кардиган, пиджак, куртка, пальто (LOOSE),
джинсы, брюки чёрные (TIGHT), юбка бежевая, ботинки чёрные.

## Что работает

- Ответ на каждый повод приходит быстро, по 3 образа, с объяснением на понятном языке («gray jacket over a
  navy sweater and beige skirt, black shoes; calm neutral colors, a warm layer for the cold»).
- Погода учитывается: при +2…+5 °C всегда есть куртка; в дождь — «a layer against the rain».
- Повод меняет образ: на прогулку — худи + джинсы + куртка (95 баллов), на собеседование и в театр — пиджак.
- Вещи с пометкой «мала / велика» не предлагаются, и об этом есть предупреждение.
- Спортзал честно отвечает «нет подходящего образа», а не подсовывает джинсы.

## Что не так (по убыванию важности)

1. **Кардиган считается основным верхом** (`catalog.py`, слот TOP). Отсюда лучший образ на собеседование и в
   театр: «куртка поверх пиджака поверх кардигана» — кардиган на голое тело и три слоя сверху.
   Нужно: кардиган — слой поверх футболки/рубашки/свитера, а не замена им.
2. **Куртка поверх пиджака** разрешена правилом «пиджак под курткой/пальто». Для повседневной куртки это
   выглядит странно; на деловой повод сверху уместно только пальто.
3. **Мало разнообразия:** «кардиган + юбка + куртка» — первый образ на свидание, вечеринку и прогулку;
   штраф за повтор действует только внутри одного ответа.
4. **Джинсы на собеседование** во 2-м и 3-м образе — формальность джинсов (2) не отсекается для повода с
   высокой формальностью, только снижает балл.
5. **Подпись повода не совпадает:** событие «Walk in the park» (FAMILY_WALK) объясняется как «Walk with kids».
6. **Нет пола у пользователя**: юбка предлагается всем; мужская фигура в примерочной её не наденет.
7. Демо-гардероб почти весь серый (вещи из 3D-каталога), поэтому цветовая часть оценки почти не работает.
8. Для спортзала нет подсказки, что добавить (спортивный низ/кроссовки), — только «нет образа».

Не проверено в браузере: страница `/events` после входа (вход в браузере по паролю — пользователем).

## Сделано по итогам (ночь на 2026-11-25)

**Лента образов `/looks`** — для телефона и ПК: карточка с образом из своего гардероба на выбранный повод и
погоду; свайп вправо/влево (мышью, пальцем, кнопками ✕ / ♥ или стрелками ← / →). Каждый свайп сохраняется как
лайк/дизлайк; уже оценённые образы больше не показываются.

**Личный вкус:** API считает вкус по всем свайпам пользователя — каждый образ даёт ±1 типам и цветам своих
вещей, вес = сумма / (число + 2), от −1 до +1. Движок сдвигает оценку образа на ±10 баллов по средней
симпатии к его вещам. На странице видно «Your taste · N swipes» с ♥/✕ по цветам и типам, на карточке —
«+0.6 your taste».

**«Complete the look»:** для каждого образа движок перебирает вещи, которых у пользователя нет (каждый тип того
же слоя × 13 цветов, плюс обувь или тёплый слой, если их нет), и предлагает одну замену, которая поднимает оценку
сильнее всего (не меньше 3 баллов), с объяснением «A navy shirt instead of your navy T-shirt lifts this outfit
from 92 to 99». Без обуви всегда предлагается подходящая пара. Не предлагается то, что пользователь свайпает
влево, и то, что исключено фильтром. Картинка — светло-серая вещь из каталога, подкрашенная в нужный цвет
(`frontend/public/shop`, 13 типов). Список покупок хранится в браузере.

**Фильтр Men / Women / All:** для «Men» API передаёт движку `avoidTypes: SKIRT, DRESS` — юбки и платья не
используются и не предлагаются. Профиль не менялся (зона тиммейтов).

**Исправлено в рекомендациях:** кардиган — слой поверх футболки/рубашки/свитера (раньше был основным верхом);
повседневная куртка не надевается на пиджак (пиджак — только под пальто); джинсы на собеседование не предлагаются.

## Проверка

- Движок: 47 тестов (`pytest`; тесты копируются в контейнер рекомендаций — в образ они не входят), из них 13
  новых: кардиган-слой, нет куртки на
  пиджаке, нет джинсов на собеседовании, вкус поднимает любимый цвет, без повторов, совет поднимает оценку и не
  из гардероба, обувь при её отсутствии, не советует нелюбимое, фильтр типов.
- API e2e внутри контейнера API (там собраны нативные модули): wardrobe, events, recommendations, admin и новый
  `feed.e2e.cjs` — все 5 проходят. Раньше они на этом компьютере не запускались.
- В браузере (тестовый аккаунт создан скриптом на странице, пароль сгенерирован там же и не сохранялся):
  - `/looks` на ПК и в размере телефона 375×812 — без горизонтальной прокрутки, свайп мышью и стрелками,
    вкус обновляется после каждого свайпа, совет «Navy shirt» с подкрашенной картинкой, список покупок;
  - гардероб: добавление вещи по фото — тип угадан («Recognized from the photo, please check», варианты
    Shirt/Sweater), цвет предложен, анализ 2.4 с, вещь сохранена с 3D-пакетом и текстурой;
  - примерочная с этой вещью открывается (3D-холст есть, ошибок нет); страница событий с прогнозом на неделю.
- Мобильная шапка: меню из 4 пунктов не помещалось — теперь переносится, страница не шире экрана.

## Не сделано

- Женское худи: расширение горловины и подрезка верха в Blender (`widen_neck.py`, `trim_top.py`) снизили
  пересечения с шеей с 7 до 3, но не до нуля — в каталог не включено, проверка не ослаблялась.
- Шорты, юбки, широкие брюки на 3D-фигуре: нет сеток (кредиты на генерацию закончились) и нет пути сборки
  низа без тела — у базового манекена под брюками нет ног, отрезать штанины нельзя.
- 3D по оставшимся 37 листам — нужны кредиты.
- Совет «докупи» — тип + цвет, не реальный товар: интеграции с магазином нет.

## Вторая половина ночи: образ на манекене и данные из фото

**Рекомендация на 3D-манекене.** В ленте `/looks` и в подборках на странице событий образ показан на 3D-фигуре:
фигура выбирается по самому внешнему слою образа (пальто, куртка, пиджак, кардиган) или по верху, нижняя футболка у
ворота — цвета внутреннего верха, брюки и обувь — цветов вещей; принт с фото ложится, если у вещи есть 3D-пакет.
Ракурсы Front / 3/4 / Back; свайп работает прямо по манекену (вращение мышью в карточке отключено).
`frontend/app/looks/OutfitFigure.tsx`.

**Данные о вещи из фото** (`frontend/lib/garment/attributes.ts`, на устройстве): узор (однотонная / узор или
принт), второй цвет, длина рукава (по точкам), тон. Для проанализированных фото — по вырезанной вещи (фон не
мешает), иначе по фото с фоном по краю. Хранятся в `wardrobe_items.attributes` (миграция
`20261125010000_item_attributes`), API проверяет строго. В форме видно «Also from the photo: pattern with black ·
short sleeve» с переключателем; в карточке вещи — строка с атрибутами.
Оценка узора на 19 фото проекта: 15 верно (`npm run eval:attributes`, отчёт `reports/stage-I77-attributes.json`).
Пропускаются мелкие и малоконтрастные принты.

**Движок учитывает:** второй цвет узорной вещи в подсчёте цветов; два узора в одном образе — −20 к цвету
(«two patterns compete»); узор на формальный повод — −8 за вещь; короткий рукав без слоя ниже +12 °C — −15 к
погоде, длинный от +25 °C — −10. В объяснении: «patterned gray T-shirt».
