# Фото вещи → вещь на 3D-теле: сквозной алгоритм

Как фото, загруженное клиентом в FitCast, превращается в вещь на 3D-фигуре. Описано то, что реально
работает на сайте (`FitCast-architechtures`), и то, чем это проверяется. Номера решений — `DECISIONS.md`.

## Коротко

```
клиент: фото ─▶ [браузер] маска U²-Netp ─▶ точки по силуэту ─▶ опорные ряды + проверка правдоподобия
                                      │                         │
                                      │      нужна проверка? ──▶ ручная правка точек в форме (верх)
                                      ▼                         ▼
                         основной цвет + текстура     пакет 3D-вещи (точки, ряды, статусы)
                                      └──────────────┬──────────┘
                                                     ▼
сервер: строгая проверка пакета и текстуры, флаг «нужна проверка» ставит сам ─▶ гардероб (БД + файлы)
                                                     ▼
примерочная: фигура с ТАКИМ ЖЕ типом вещи ─▶ перенос фото на лицевые грани ─▶ ползунки фигуры
```

Фото для распознавания никуда не отправляется: маска, точки и цвет считаются в браузере. На сервер уходят
само фото (для гардероба), текстура и пакет.

## Шаги

### 1. Загрузка (клиент, `frontend/app/profile/Wardrobe.tsx`)
Человек выбирает фото и тип вещи. Принимаются JPEG, PNG и WebP до 8 МБ. Для футболок, рубашек, худи, свитеров,
брюк и джинсов сразу запускается распознавание. Для остальных типов вещь сохраняется только с цветом.

### 2. Маска (браузер, `lib/garment/analyze.ts`)
- Фото уменьшается до 1024 px по длинной стороне.
- Маску строит U²-Netp 320×320 в onnxruntime-web (wasm). Хеш модели совпадает с проверенным. Лицензия кода
  и весов — `public/models/README.md`.
- Постобработка `post-v3`: порог, крупнейшая связная область, закрытие мелких дыр; фон, который модель захватила
  (стена между штанинами, ткань под подолом), возвращается фону (I-66).
- Оценка маски: ok, suspicious или empty. Это эвристика, а не точность (D-20).

### 3. Точки по силуэту (`lib/garment/landmarks.ts`, `photoMap.ts`)
- **Верх** (футболка, а с I-63 и рубашка, худи, свитер): 13 точек — ворот ×3, плечи, подмышки, манжеты ×4,
  углы низа. По точкам и маске снимаются боковые края на линиях низа, талии, груди и проймы.
- **Брюки и джинсы**: пояс, промежность, бёдра, низ штанин. Края сиденья (5 рядов) и штанин (9 рядов)
  снимаются с маски.
- Если вещь обрезана краем кадра, точки помечаются «нужно подтвердить» (I-66).
- `anchorIssues` проверяет правдоподобие. Например, раскрыв манжеты больше ширины низа значит, что
  рукава висят вдоль тела. Такой снимок получает пометку «нужно подтвердить точки».

### 4. Ручная правка точек (верх, I-63)
Если точки неуверенные или неправдоподобные, форма показывает «Поправить точки». Человек перетаскивает
13 точек мышью или пальцем. Опорные ряды и правдоподобие пересчитываются тем же кодом, а пакет помечается
`pointsSource: 'user'`. Без правки такой пакет сохраняется с флагом «нужна проверка», и в примерочной
показывается предупреждение.

### 5. Цвет и текстура
Основной цвет — медиана пикселей внутри маски. Текстура — само фото, где всё вне маски залито основным
цветом, поэтому фон не протекает на вещь.

### 6. Сервер (`src/wardrobe/garment3d.ts`, `wardrobe.controller.ts`)
- Пакет разбирается строго: известные ключи, конечные числа в пределах снимка, точное число рядов, цвет
  `#rrggbb`. Текстура проверяется по байтам.
- Категория пакета должна подходить к типу вещи:
  - `tshirt` → футболка;
  - `top` → рубашка, худи, свитер;
  - `pants` → брюки, джинсы.
- Флаг «нужна проверка» сервер ставит сам по статусам. Клиенту в этом не доверяется.

### 7. Выбор фигуры (`frontend/app/fitting/FittingRoom.tsx`, I-54)
Вещь надевается только на фигуру, у которой такой же тип вещи (`figures.json → garments`):
- футболка → фигура в футболке;
- рубашка → фигура в рубашке;
- худи → фигура в худи;
- брюки → фигура в брюках.

Если такой фигуры нет, выводится сообщение «3D-модели с этой вещью пока нет», и ничего не надевается.
Ссылка «Примерить на 3D» из гардероба (`/fitting?item=<id>`) сама выбирает фигуру и надевает вещь.

### 8. Перенос фото на фигуру (`lib/figure/photoMap.ts` = `imported-body/src/photoMap.ts` дословно)
- У оболочек фигуры нет UV. Каждая лицевая грань верха или низа получает координаты на снимке по тем же
  ориентирам:
  - торс — рядами низ → талия → грудь → пройма → плечи и горловина;
  - рукава — от плеча и подмышки к манжете;
  - брюки — сиденье и каждая штанина отдельно.
- Координаты считаются по канонической фигуре, поэтому ползунки их не меняют.
- Спинка, бока и всё, чего нет на снимке, закрашиваются основным цветом. Спинка не восстанавливается и не
  зеркалится с переда (D-17).

### 9. Фигура и ползунки (`lib/figure/deform.ts`)
- Фигуры готовит модуль `imported-body`: импорт, сегментация на части, слои одежды (I-61/I-62), проверки.
- В клиент они попадают командой `npm run figure:sync`.
- Ползунки (грудь, талия, бёдра, плечи, руки, ноги, рост) двигают тело вместе с одеждой в измеренном
  рабочем диапазоне каждой фигуры.
- «Пропорции как у людей» (I-68): рост и вес меняют всю фигуру, ползунки обхватов — форму при том же весе;
  остальные обхваты подстраиваются по корреляциям замеров ANSUR II (`lib/figure/proportions.ts`).

## Проверки

| Что | Команда | Блокирует |
|---|---|---|
| Перенос фото на все фигуры: 14 футболок, 2 вещи с длинным рукавом, 3 брюк (I-66: предупреждений 4 из 19 снимков) | `npm run ib:photo` (3dmodel) | да: стороны, переворот, ось рукава, ≤ 3 % перевёрнутых граней — на снимках, где точки «ok» |
| Фигуры с одеждой: пересечения, ползунки | `npm run ib:outfits` (3dmodel) | да |
| Сервер: пакеты всех категорий, битые пакеты, чужие типы, ручные точки | `npm run test:wardrobe` (FitCast) | да |
| Типы клиента | `npx tsc --noEmit` (frontend) | да |

## Чего алгоритм не делает

- Не меряет сантиметры по фото: масштаба на снимке нет.
- Не восстанавливает спинку и не моделирует ткань: вещь — это одежда фигуры с принтом с фото, а не
  отдельно сшитая сетка.
- Нет фигур для курток, пальто, юбок, шорт и платьев. Такие вещи сохраняются в гардероб, но не надеваются.
- Ручной правки точек брюк на сайте нет: они либо распознаны, либо помечены «нужна проверка».
- Распознавание идёт в основном потоке браузера, поэтому интерфейс замирает примерно на 2 с.
